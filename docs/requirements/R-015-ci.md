# R-015 CI: gate PRs on build + unit + e2e — ✅ done

Why: `main` is protected (PRs only). Broken code shouldn't merge. The tests that
caught the real bugs this project hit (missing grade column, blank page) must
run before merge, not just locally.

Done when: a GitHub Actions workflow runs on PRs to `main` and must pass to
merge — build + unit (vitest) in one job, e2e (Playwright on local Supabase) in
another. ✅ (`.github/workflows/ci.yml`.)

## Shape

- `npm test` aggregates `test:unit` (vitest) + `test:e2e` (playwright) so it's
  one command and hard to forget a layer; CI runs them as two parallel jobs.
- e2e job uses `npx supabase start` — the CLI owns the Docker containers, same
  as local; no bespoke Dockerfile (would be Docker-in-Docker and diverge from
  the local harness).
- Unit tests: `src/**/*.test.ts` (vitest `include`); e2e stays Playwright's.
  SM-2's old in-file self-check was ported to `src/lib/scheduler.test.ts`.

## Not verified

GitHub Actions can't be run locally; the exact command sequence was reproduced
on a clean clone (`npm ci` + build) and `npm test` passes locally. First real
proof is the first PR's check run.
